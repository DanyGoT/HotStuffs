#+title: Requirements from the papers

Terse restatement of what the DiemBFT proofs need. Code pointers are
=file.go:Func= in =diem/=. The paper has three validator kinds: Byzantine
(fully adversarial), compromised (adversarial outside Safety) and honest;
"non-Byzantine" = honest + compromised.

* 1. Model and assumptions
- At most f < n/3 Byzantine; quorum = 2f+1 for n = 3f+1 (=quorum.go:QuorumSize=, =Faulty=).
- Any two quorums share >= 1 non-Byzantine validator; any quorum holds >= f+1.
- Signatures unforgeable; hashes collision-resistant; private key lives only in Safety
  (=safety.go:Safety=).
- Partial synchrony: GST happens after an unknown finite time; a message sent at t
  arrives by max{t, GST}+\Delta, with \Delta known.
- Transport delivers reliably and fetches referenced data; Lemma 6 needs finite
  timeouts and delays.
- Round-r proposal/timeout is well-formed iff it carries TC(r-1) whenever its qc is
  not from r-1. Honest replicas send only well-formed messages and discard others.
- Non-Byzantine replicas vote at most once per round and never lower their counters.
- Compromised replicas may commit anything locally (commit info lives outside Safety)
  but cannot make honest ones violate Agreement.

* 2. DiemBFT v4 (2-chain; the protocol this code implements)
** Definitions
- Def 1 global direct-commit: B is globally direct-committed iff f+1 non-Byzantine
  replicas =make_vote= on some B' in round B.round+1 with B'.qc certifying B
  (setting highest_qc_round = B.round).
- Def 2 local direct-commit: replica calls =Ledger.commit(B)= only on observing
  B <- QC_B <- B' <- QC_B' with B'.round = B.round+1
  (=blocktree.go:ProcessQC=, =types.go:Commits=, =safety.go:commitStateIDCandidate=).
** Safety (Agreement)
- Lemma 1: local direct-commit => global direct-commit.
- Lemma 2: if B is globally direct-committed, every TC of a higher round has
  max(tmo_high_qc_rounds) >= B.round.
- Property 1: once a block is certified in a round, no other block gathers f+1
  non-Byzantine votes in it, so at most one block is certified per round.
- Lemma 3: if B is globally direct-committed, every certified B' with
  B'.round >= B.round extends B.
- Property 2: any two globally direct-committed blocks are on one chain; every committed
  block is one or is extended by one, so committed prefixes never conflict.
** Liveness
- Lemma 4: honest replica in round < r receiving a proposal or timeout for round r
  from an honest sender enters round r
  (=pacemaker.go:AdvanceRoundQC=, =AdvanceRoundTC=).
- Lemma 5: if QCs form in all rounds > r, infinitely many rounds > r have honest
  elected leaders.
- Lemma 6: with finite timeouts and delays, honest replicas enter ever-increasing rounds.
- Property 3 (liveness): after GST every honest replica eventually commits a block of
  a round > r.
- Lemma 7: honest leader's proposal in a round with no QC and no honest timeout =>
  =make_vote= returns a vote (not nil).
- Lemma 8: all honest agree on honest leader of r, r after GST => all enter r within
  2\Delta of each other.
- Lemma 9: honest agreed leaders for r, r+1 after GST => B_r globally direct-committed
  within 5\Delta of first honest entry.
- Property 4: honest agreed leaders for r, r+1, r+2 after GST => every honest replica
  locally direct-commits B_r within 7\Delta.
** Leader reputation (t = actual faults)
- Requirements: t-leader-utilization, liveness, t-chain-quality. Reputation is a
  deterministic function of committed history, so after GST replicas disagree on a
  leader only a small number of times.
- Lemma 10: a committed Byzantine block of round r whose author leads a reputation
  round r' >= r+3 => >= exclude_size-t+1 honest committed blocks in between.
- Lemma 11: r after GST, rounds r and r+1 share an honest round-robin leader => a block
  of round r-3, r-2 or r is committed.
- Lemma 12: h honest committed blocks in [r, r+6f+1], r even after GST =>
  >= 2f+1-3h committed Byzantine blocks in [r-3, r+6f-2].
- Theorem 13: after GST an honest block commits within O(f log((2f+1)/(2f+1-2t)))
  rounds.
- Cor 1: t = f, exclude_size = 2f => O(f log f) commits per honest commit worst case,
  O(f) on average. exclude_size in [f, 2f] is a parameter note, not a hypothesis.
- Lemma 14, Cor 2: after GST at most (p+1)t(6f+6) rounds fail to crashes,
  p = ceil(3 window_size/(2f+1)).
- Property 5: O(t max(window_size, f))-leader-utilization.

* 3. HotStuff (PODC'19): 3-chain basic/chained, which DiemBFT generalises
Not implemented here (we commit on a 2-chain); kept for the proof structure.
- Lemma 1: two valid QCs of the same type on conflicting nodes have different views
  (one vote per phase per view). Counterpart: DiemBFT Property 1.
- Theorem 2 (safety): conflicting nodes cannot both be committed by correct replicas.
  Counterpart: DiemBFT Property 2. Proof uses the lock (=lockedQC=) and =safeNode=:
  vote only if node extends lockedQC.node, or justify.view > lockedQC.view. DiemBFT
  replaces the lock with highest_qc_round plus highest_vote_round; the TC rule carries
  it across rounds (Lemma 2).
- Lemma 3: a correct replica locked on precommitQC implies f+1 correct replicas voted
  for the matching prepareQC. Counterpart: DiemBFT Lemma 2 (via tmo_high_qc_rounds).
- Theorem 4 (liveness): after GST, bounded T_f, all correct replicas in view v with a
  correct leader => decision. Counterpart: DiemBFT Lemma 9, Property 3.
- Theorem 5 (chained HotStuff safety, App. A): conflicting nodes cannot both be
  committed via a three-chain. Counterpart: DiemBFT Lemma 3, Property 2.
- App. B, Lemma 6: same-height conflicting nodes cannot both have valid QCs. Lemma 7:
  conflicting nodes cannot both be committed by honest replicas. Theorem 8: honest
  replicas execute commands in a consistent order. All 3-chain specific.
- Doesn't apply: lock/precommit/commit phases, view-change messages, three-chain commit;
  HotStuff has no TC or reputation scheme. The "livelessness with two phases" argument is
  the one DiemBFT answers with the TC condition.

* Gaps / unverified
Lemma numbers here are DiemBFT's.
- No persistence: =highest_vote_round= / =highest_qc_round= are in memory only, so a
  restart can violate Lemma 2 and Property 1 (paper: =save_consensus_state=;
  =pacemaker.go:LocalTimeoutRound= notes the omission).
- No block-sync: =safety.go:MakeVote= declines when an ancestor was never speculated
  (=DeclinedMissingAncestor=), so Lemma 7 (honest leader's proposal gets a vote) and the
  Lemma 9 / Property 4 timing bounds do not hold under reordering or loss.
- =QuorumSize= is ceil((n+f+1)/2), equal to 2f+1 only when n = 3f+1; for other n it
  is above it, safe but not what the paper's liveness counts assume.
- Genesis QC is trusted by id only (=verify.go:VerifyQC=), by design.
- Leader election: exclude_size in [f, 2f] and window_size large enough that
  active \ last_authors is non-empty are config assumptions; the code falls back to
  round-robin on an empty difference rather than enforcing them
  (=leader.go:electReputationLeader=, =core.go:New= defaults).
- =Backoff= is capped; liveness needs the cap above the post-GST round time.
- Lemma 7 / Lemma 8 rely on the vote-lead bound (=core.go:maxRoundLead=, a memory
  bound) and dropping of timeouts for past rounds not discarding messages an honest
  peer needs; not argued in the paper.
