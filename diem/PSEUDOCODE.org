#+title: DiemBFT v4 section 3, procedure by procedure

Where each procedure of the paper's section 3 pseudocode landed in this
package, and where it did not land verbatim.

The pseudocode itself is *not* reproduced here. The transcription is
=.claude/notes/diembft-pseudocode.md=, and it is the canonical copy: a second
one would drift. What follows restates each procedure in this codebase's
vocabulary and points at the code.

Bare file names are in =diem/=; anything else is written from the repository
root. Line numbers are paired with the Go identifier, so a reference survives
the line drifting.

=README.org= covers what the package is and how it is laid out. This file
covers only the mapping.

* 3.1 Main

** EventLoop

The paper's outer loop. Split in three here, because the core is drivable at
three levels: =Core.Step= for state-machine unit tests, =Loop.Tick= for the
deterministic harness, =Loop.Run= in production.

- Implemented :: =loop.go:52= =Loop.Run=, =loop.go:40= =Loop.Tick=,
  =events.go:30= =Queue=, =events.go:36= =Queue.Push=.
- Differs :: structurally only. The queue is the goroutine boundary and the
  only backpressure point in the replica; the paper has no concurrency model to
  place one in. No protocol difference.

** start_event_processing(M)

One switch over the sealed =Event= set, so the dispatch is exhaustive by
construction and needs no default case.

- Implemented :: =core.go:153= =Core.Step=; the event set is =events.go:7=
  =Event= with its four members.
- Differs :: the paper dispatches a local timeout unconditionally. =core.go:173=
  runs =Pacemaker.LocalTimeoutRound= only when the event's =Round= is still
  =Pacemaker.CurrentRound()=. The timer callback runs off the consensus
  goroutine and only enqueues, so a callback that had already fired when
  =startTimer= or =Stop= disarmed the timer is still sitting in the queue;
  running it would abandon a round the replica entered on a good certificate.

** process_certificate_qc(qc)

Feed the certificate to the block tree, then to leader election, then to the
pacemaker.

- Implemented :: =core.go:182= =Core.processCertificateQC=.
- Differs :: only in two details. A nil guard at =core.go:183=, because
  =HighCommitQC= is optional on the wire. And the paper's
  =Pacemaker.advance_round(qc.vote_info.round)= is =AdvanceRoundQC(qc)= here —
  see *Where the paper is self-contradictory*, item 1. The order is the
  paper's, and it matters: =LeaderElection.UpdateLeaders= reads the round the
  certificate arrived in, so it must run before the pacemaker advances past it.

** process_proposal_msg(P)

Advance on all three certificates the proposal carries, then check that the
block's round is the current round and that its sender and author both lead it,
then speculate and insert, then vote.

- Implemented :: =core.go:194= =Core.processProposalMsg=; the vote goes out at
  =core.go:215= to =LeaderElection.GetLeader(round+1)=, unicast, as the paper
  specifies.
- Differs :: no protocol difference. What changed is *where* authentication
  happens: signatures, quorum sizes, certificate well-formedness and signer
  order are checked at the edge (=diemnet/server.go:36=, =Verifier.VerifyProposal=
  at =verify.go:95=) before the message is queued. The three checks that remain
  here are the paper's own, and the leader check could not move anyway —
  =GetLeader= has a reputation path keyed on committed blocks, so a round's
  leader is a function of protocol state.

** process_timeout_msg(M)

Advance on the timeout's =HighQC=, its =HighCommitQC= and its =LastRoundTC=,
then accumulate it; a TC that completes advances the round and fires a new-round
event.

- Implemented :: =core.go:218= =Core.processTimeoutMsg=.
- Faithful :: no deviation.

** process_vote_msg(M)

Accumulate the vote; a certificate that completes is processed and a new-round
event fires.

- Implemented :: =core.go:231= =Core.processVoteMsg=.
- Differs :: a round-lead bound precedes the paper's body. =core.go:232=
  drops a vote claiming a round more than =maxRoundLead= (=core.go:125=, 4)
  above the current one. The paper has no bound. Votes bucket on a digest over
  a =LedgerCommitInfo= its sender picks freely, and nothing a receiver can check
  binds the round a vote claims, so without the bound one sender opens one
  bucket per message and only a commit — needing a quorum those votes can never
  reach — would prune them.

** process_new_round_event(last_tc)

If this replica leads the round it just entered, build a block over =HighQC=,
sign its id and broadcast the proposal.

- Implemented :: =core.go:247= =Core.processNewRoundEvent=. The payload comes
  from =Config.Transactions= (=core.go:47=), nil-checked at =core.go:253=,
  which is this package's MemPool seam. =core.go:257= is the only =crypto=
  call in =core.go=.
- Differs :: the paper forwards =last_tc= verbatim. =core.go:263= passes it
  through =justifyingTC= (=core.go:273=), which returns nil when the block's own
  QC is already from round-1. Forwarding it would produce a proposal that the
  paper's own well-formedness rule makes ill-formed, and that every honest
  replica — including one running the paper's =process_proposal_msg= —
  discards. See *Where the paper is self-contradictory*, item 2.

* 3.2 Ledger

** speculate(prev_block_id, block_id, txns)

Execute a block's payload over its parent's speculated state and store the
result under the block id.

- Implemented :: =ledger.go:75= =MemLedger.Speculate=; the VM is the
  =Execute= field (=ledger.go:14=), defaulting to =ExecuteHash= (=hash.go:116=).
- Differs :: two things. The signature takes the whole =*Block= rather than the
  paper's three fields — all three are fields of the block, and
  =committed_block= must hand a whole block back, so the ledger holds it
  regardless. And a parent this replica never speculated stores *nothing* and
  returns the zero state (=ledger.go:76-78=). That is where the paper's missing
  block-sync lands: section 3 defines no way to fetch a block, so a replica
  that loses one proposal cannot speculate it, cannot vote on it, and cannot
  speculate its children either.

** pending_state(block_id)

The speculated state for a block, or absent.

- Implemented :: =ledger.go:87= =MemLedger.PendingState=.
- Differs :: the last committed block answers too (=ledger.go:88-90=). Its
  children extend it and it is no longer in the pending map, so without this a
  block extending the commit frontier could never be speculated. The paper does
  not say either way.

** commit(block_id)

Commit the pending prefix ending at a block and discard the branches forking
below it.

- Implemented :: =ledger.go:97= =MemLedger.Commit=; branch discard is
  =ledger.go:136= =MemLedger.prune=, which drops orphans to a fixpoint.
- Differs :: two early returns the paper does not have. =ledger.go:98= returns
  when the block is already the frontier, which is the common case since every
  QC re-commits. =ledger.go:107= returns when the block is not a descendant of
  the frontier — the missing-ancestor gap again, seen from the commit side: the
  frontier cannot walk back across a block that was never speculated.
  =ledger.go:153= =MemLedger.forget= is a retention bound with no counterpart
  at all; see *Code with no counterpart in the paper*.

** committed_block(block_id)

A committed block by id, which is what =LeaderElection= walks back over.

- Implemented :: =ledger.go:128= =MemLedger.CommittedBlock=.
- Faithful :: no deviation, except that the answer is bounded by =History=
  (=ledger.go:21=, default =ledger.go:40=) rather than being a permanent store.

* 3.3 Block-tree

The paper defines the message types here as well as the module. Those first.

** The data types

- =VoteInfo= :: =types.go:42=.
- =LedgerCommitInfo= :: =types.go:57=; the paper's bottom =commit_state_id= is
  the zero hash, tested by =types.go:63= =LedgerCommitInfo.Commits=.
- =VoteMsg= :: =types.go:68=.
- =QC= :: =types.go:77=, with =types.go:90= =QC.Round= and =types.go:99=
  =higher=, which is the paper's =max_round{}=.
- =Block= :: =types.go:108=, built by =types.go:118= =NewBlock=; the id
  formula =hash(author || round || payload || qc.vote_info.id || qc.signatures)=
  is =hash.go:55= =blockID=.
- =TimeoutInfo= :: =types.go:133=.
- =TC= :: =types.go:154=, plus =types.go:162= =TC.MaxHighQCRound=, the paper's
  =max(tc.tmo_high_qc_rounds)=.
- =TimeoutMsg= :: =types.go:177=. =ProposalMsg= :: =types.go:185=.
- Well-formedness :: the paper states it as prose, not pseudocode; it is
  =types.go:208= =wellFormed= with the two entry points =types.go:197=
  =ProposalMsg.WellFormed= and =types.go:203= =TimeoutMsg.WellFormed=.

One deviation in the types: the paper keeps a TC's =tmo_high_qc_rounds= and
=tmo_signatures= in two parallel vectors. =types.go:147= =TimeoutVote= is one
slice of pairs instead. Each signature covers =(tc.Round, its own HighQCRound)=,
so verifying against the wrong partner would silently succeed for a different
sender, and parallel vectors are exactly the shape that permits that.

** process_qc(qc)

A certificate whose =LedgerCommitInfo= names a committed state commits that
block's *parent*, prunes the tree to it, and raises =high_commit_qc=; every
certificate raises =high_qc=.

- Implemented :: =blocktree.go:81= =BlockTree.ProcessQC=; the tree prune is
  =blocktree.go:156= =BlockTree.prune=.
- Faithful :: no deviation. =prune= takes the root's round from the certificate
  rather than from a lookup (=blocktree.go:156=), because the root may already
  have been pruned by an earlier commit and the QC carries its round.

** execute_and_insert(b)

Speculate the block, then add it to the pending tree.

- Implemented :: =blocktree.go:94= =BlockTree.ExecuteAndInsert=.
- Faithful :: no deviation.

** process_vote(v)

Process the vote's commit certificate, bucket the vote by the digest of its
=LedgerCommitInfo=, and return a QC once a bucket reaches quorum.

- Implemented :: =blocktree.go:105= =BlockTree.ProcessVote=; the author
  signature is produced at =blocktree.go:129= over =hash.go:105= =qcSigsDigest=,
  and checked on receipt at =verify.go:50= inside =Verifier.VerifyQC=.
- Differs :: three things.
  1. The paper accumulates a *set union over signatures*. With a randomised
     signature scheme two signatures by one replica differ byte for byte, so
     the union would not deduplicate and one sender could reach quorum alone.
     Deduplication is by signer.
  2. Deduplication is by =voterKey{round, signer}= (=blocktree.go:41=), checked
     at =blocktree.go:108-111= *before* the bucket is created, not within a
     bucket. The bucket key is a digest over fields the sender chooses, so a
     signer varying one of them opens a bucket per message without ever
     repeating itself inside one. An honest replica votes at most once per
     round — =safeToVote= requires the block's round to exceed
     =highestVoteRound=, which never decreases — so one entry per
     (round, signer) is all that can ever be legitimate.
  3. =blocktree.go:124= canonicalises the signature set and =blocktree.go:133=
     drops the bucket once the certificate exists.

** generate_block(txns, current_round)

A block for the current round over the highest certificate known.

- Implemented :: =blocktree.go:146= =BlockTree.GenerateBlock=, over
  =types.go:118= =NewBlock= and =hash.go:55= =blockID=.
- Faithful :: no deviation.

- Implemented :: =safety.go:49= =consecutive=.
- Faithful :: no deviation.

** safe_to_extend(block_round, qc_round, tc)

A block may skip rounds only behind a TC for the round directly below it, and
only when its certificate is at least as high as every certificate that TC's
quorum reported.

- Implemented :: =safety.go:56= =Safety.safeToExtend=, over =types.go:162=
  =TC.MaxHighQCRound=.
- Differs :: a nil guard at =safety.go:57=. The paper dereferences =tc.round=
  and =tc.tmo_high_qc_rounds= with no guard, while =safe_to_vote= calls it with
  a =tc= that may be nil.

** safe_to_vote(block_round, qc_round, tc)

Vote in monotonically increasing rounds, over a round strictly below this one,
and only when the QC or a TC justifies the round.

- Implemented :: =safety.go:63= =Safety.safeToVote=.
- Faithful :: no deviation.

** safe_to_timeout(round, qc_round, tc)

Never report a =high_qc= below one already endorsed, never time out of a past
round, and only time out of a round the QC or a TC justified entering.

- Implemented :: =safety.go:77= =Safety.safeToTimeout=.
- Differs :: two corrections, neither of them a change of intent. The paper
  writes =max(highest_vote_round - 1, qc_round)=; rounds are unsigned here, so
  round 0 is subtracted explicitly rather than wrapping (=safety.go:83-86=).
  And the =tc= nil guard again, at =safety.go:90=.

** commit_state_id_candidate(block_round, qc)

The 2-chain commit rule: a vote for a block whose round directly follows its
parent's carries the parent's speculated state, so the quorum certifying the
block also certifies that commit. A gap in rounds commits nothing.

- Implemented :: =safety.go:97= =Safety.commitStateIDCandidate=.
- Faithful :: no deviation. "Commits nothing" is the zero hash, which is the
  paper's bottom.

** make_vote(b, last_tc)

Re-verify the certificates, apply =safe_to_vote=, raise both counters, then
build the =VoteInfo= and =LedgerCommitInfo= and sign the latter.

- Implemented :: =safety.go:110= =Safety.MakeVote=.
- Differs :: the paper puts =Ledger.pending_state(b.id)= inside the =VoteInfo=
  and would sign a bottom execution state when the lookup fails. =safety.go:120=
  declines instead, and counts the decline. A vote is a claim about an
  execution result, and a replica that could not execute the block — because it
  never saw an ancestor, and the paper has no block-sync — has no result to
  claim. Note the ordering consequence: the counters move only on the path that
  produces a vote, so a declined vote does not burn the round.

** make_timeout(round, high_qc, last_tc)

Re-verify, apply =safe_to_timeout=, raise =highest_vote_round= to stop voting
in the round, and sign =(round, high_qc.round)=.

- Implemented :: =safety.go:156= =Safety.MakeTimeout=; the digest is
  =hash.go:96= =TimeoutDigest=.
- Faithful :: no deviation.

** valid_signatures(b, last_tc)

The paper calls this from both public procedures but never defines it.

- Implemented :: =safety.go:172= =Safety.validSignatures=, which routes to
  =verify.go:29= =Verifier.VerifyQC= and =verify.go:73= =Verifier.VerifyTC= —
  the same implementations the edge uses. Safety re-verifies deliberately: it
  holds the private key and is the one module assumed to survive the rest being
  compromised.

* 3.5 Pacemaker

** get_round_timer(r)

The paper leaves the formula open — "4*delta, or alpha + beta*commit_gap(r) if
delta is unknown".

- Implemented :: delegated to the exponential backoff both protocols in this
  repository share: =hotstuff/duration.go:8= =hotstuff.Duration=, read at
  =pacemaker.go:83= and fed by =pacemaker.go:81= =ViewStarted=,
  =pacemaker.go:93= =ViewTimedOut= and =pacemaker.go:180= =ViewSucceeded=.
- Differs :: a choice within the paper's latitude rather than a deviation.
  There is no =Pacemaker= method of this name; the policy is a field.

** start_timer(new_round)

Stop the running timer, enter the new round, arm a timer for it.

- Implemented :: =pacemaker.go:73= =Pacemaker.startTimer=.
- Differs :: it also prunes =pendingTimeouts= below the new round
  (=pacemaker.go:76-80=). The paper's comment says only the current round's
  timeouts are needed but never drops the others. The timer callback may only
  enqueue (=pacemaker.go:84=), since it runs off the consensus goroutine.

** stop_timer(current_round)

- Implemented :: =pacemaker.go:62= =Pacemaker.Stop=.
- Differs :: no round argument. There is exactly one timer, so there is nothing
  to select.

** local_timeout_round()

Build this replica's timeout for the current round and broadcast it.

- Implemented :: =pacemaker.go:92= =Pacemaker.LocalTimeoutRound=.
- Differs :: four things.
  1. =save_consensus_state()= is absent — see *Procedures with no counterpart*.
  2. =pacemaker.go:95= returns when =MakeTimeout= declines. The paper
     broadcasts a =TimeoutMsg= built around the result unconditionally.
  3. =pacemaker.go:106= passes =lastRoundTC= through =justifyingTC=, for the
     same reason and by the same rule as the proposal path. See *Where the
     paper is self-contradictory*, item 3.
  4. =pacemaker.go:112= re-arms the timer. The paper stops it and waits for a
     TC, which leaves a replica whose broadcast was lost with no timer at all;
     here the timeout is retransmitted until a QC or a TC moves the round.

** process_remote_timeout(tmo)

Accumulate a timeout for a round not already behind us; at f+1 senders time out
locally as well (Bracha amplification), at 2f+1 return the TC.

- Implemented :: =pacemaker.go:122= =Pacemaker.ProcessRemoteTimeout=; the
  thresholds are =pacemaker.go:144= and =pacemaker.go:147=.
- Differs :: two things.
  1. =pacemaker.go:132= returns early on a duplicate sender. The paper puts its
     two count tests *outside* the duplicate guard, and re-adding a sender to a
     set does not change its size, so a resent timeout re-runs both: a second
     Bracha broadcast, and a second TC for a round already abandoned, which then
     drives an ill-formed proposal. This implementation retransmits timeouts
     while a round is stuck, so the duplicate is certain, not hypothetical.
  2. =pacemaker.go:156= sorts the assembled TC's votes into signer order.
     Timeouts arrive in whatever order the network delivers them, and a receiver
     rejects a non-canonical certificate (=verify.go:82=), so a replica whose
     timeouts arrived out of ID order would otherwise assemble a TC that neither
     its peers nor its own =Safety.validSignatures= would accept.

- Faithful :: no deviation.

** advance_round_qc(qc)

* 3.7 LeaderElection

** get_leader(round)

The reputation-elected leader when one was elected for the round, otherwise
round-robin with two rounds per leader:

#+begin_example
validators[(round / 2) mod |validators|]
#+end_example

- Implemented :: =leader.go:52= =LeaderElection.GetLeader=.
- Faithful :: no deviation. =validators= is sorted at construction
  (=leader.go:34-35=) so every replica indexes the same rotation.

** update_leaders(qc)

Elect the leader of the round after next, but only when the certificate shows a
contiguous 2-chain that this replica is exactly one round past.

- Implemented :: =leader.go:65= =LeaderElection.UpdateLeaders=; the predicate
  is =leader.go:72=.
- Differs :: three additions, none of them to the predicate. A nil guard
  (=leader.go:66=); the write happens only when the election succeeded
  (=leader.go:75-77=, see below); and =leader.go:78-82= drops entries for rounds
  already left behind, which the paper's map would accumulate forever.

** elect_reputation_leader(qc)

Walk back over committed blocks collecting the signers of the last
=window_size= certificates and the authors of the last =exclude_size= blocks,
then pick deterministically from the difference, seeded on the certificate's
round.

- Implemented :: =leader.go:92= =LeaderElection.electReputationLeader=;
  =pick_one(seed)= is =leader.go:136= =pick=, which hashes the round rather than
  taking it modulo the candidate count, so consecutive seeds spread across the
  set.
- Differs :: two termination guards the paper's loop lacks. =leader.go:99-101=
  and =leader.go:111-113= stop when the ledger no longer holds the next block
  back, which happens both early in a run and once =History= has dropped old
  blocks; the paper's loop runs off the end of a short history.
  =leader.go:122-127= returns "no election" when the difference is empty — the
  paper argues it is non-empty, which holds only once the window is full — and
  round-robin then stands, the same fallback a replica that saw no commit uses.
- Reproduced faithfully, and worth knowing :: the walk steps over *alternating*
  committed blocks, not consecutive ones. Each iteration looks up
  =current_qc.vote_info.parent_id= and then sets =current_qc <- current_block.qc=,
  which skips a block per step. That is the algorithm as the paper specifies it.

* Procedures with no counterpart

- =save_consensus_state()= (3.5, called from =local_timeout_round=) :: the two
  counters it would persist are =Safety='s (=safety.go:17-18=), and this is a
  prototype with no durable state, so persisting them would have nothing to
  recover into. Recorded at the site, =pacemaker.go:90-91=. A replica that
  restarts here restarts from genesis; the paper's version could restart from
  its last vote.

Two more are implemented but not as procedures, noted so nobody hunts for them:
=get_round_timer= is a policy field rather than a method (=pacemaker.go:19=),
and =stop_timer= drops its round argument (=pacemaker.go:62=).

* Code with no counterpart in the paper

Section 3 is a protocol, not a program. These are what it takes to run one.

- Bootstrap :: =core.go:130= =Core.Start= — advance on the genesis certificate
  and fire the first new-round event. The paper never says how round 1 begins.
  The genesis block and its certificate are =genesis.go:11=: two objects, not
  one, because a block's id covers a QC but no certificate can name the genesis
  block before its id exists.
- The edge verifier :: =verify.go:13= =Verifier=, called from
  =diemnet/server.go:36=, =:45= and =:54=. The paper's only verification hook is
  =valid_signatures= inside =Safety=. Splitting it out is what lets signature
  checking run on the handler goroutines, in parallel across senders. Two of
  its checks have no paper counterpart at all: =verify.go:102= rejects a block
  whose QC is not from a round below its own (well-formedness permits it on the
  TC branch, and =safeToVote= catches it only after the pacemaker has advanced
  and the block has been speculated), and =verify.go:78= rejects a TC for round
  0, which no replica ever times out of.
- Canonical certificate encoding :: =blocktree.go:192= =canonical=,
  =pacemaker.go:156=, and the strict-increase checks at =verify.go:61-65= and
  =verify.go:82=. A block id covers its parent certificate's signature slice
  byte for byte (=hash.go:55=), so one quorum left unordered is one quorum's
  worth of distinct, individually valid block ids, each entering the block tree
  and the speculation tree.
- The round-lead bound :: =core.go:125= =maxRoundLead=, applied at
  =core.go:232=. Nothing in the paper bounds how far ahead an inbound vote may
  claim to be.
- The missing-ancestor counter :: =safety.go:20= and =safety.go:39=
  =Safety.DeclinedMissingAncestor=, incremented at =safety.go:122= and surfaced
  through =core.go:72= =State.DeclinedMissingAncestor=. Section 3 has no
  block-sync and none was added; this counter is the price tag. It is the
  number the report should quote about the gap, rather than an argument about
  whether section 3 is livelocked in principle.
- Retention :: =ledger.go:21= =History= and =ledger.go:153= =MemLedger.forget=.
  The paper's ledger is unbounded; =committed_block= must still answer for
  everything =elect_reputation_leader= walks back over, so the bound is what
  =electReputationLeader='s termination guard exists for.
- The event queue and driver :: =events.go:30= =Queue=, =loop.go:11= =Loop=.
  The goroutine boundary, the only backpressure point, and the queue high-water
  mark.
- The outbound seam :: =transport.go:7= =Transport=, the only interface the
  package declares. The paper writes "send" and "broadcast".
- Domain-separated digests :: =hash.go:12=. The paper writes =hash()=. Six
  distinct tags keep a vote signature from ever verifying as a timeout
  signature, or either as a block id.
- Observability :: =core.go:62= =State=, =core.go:139= =Core.State=, and the
  =Observer= hook at =core.go:58=.
- MemPool ingress :: =mempool.go:21= =FIFOPool.Add=.

* Where the paper is self-contradictory

Three places, and they are the most interesting material here for the report:
all three are cases where following section 3 literally produces behaviour that
section 3 itself rejects.

** 1. advance_round is called by a name that does not exist

=process_certificate_qc= calls =Pacemaker.advance_round(qc.vote_info.round)=
and =process_timeout_msg= calls =Pacemaker.advance_round(tc)= — one with a
round, one with a certificate. The Pacemaker module (3.5) defines neither; it
defines =advance_round_qc(qc)= and =advance_round_tc(tc)=. Read as the typed
pair, which is what =core.go:188= and =core.go:221= implement. Harmless, but it
is the reason a reader comparing the two modules side by side finds no match.

** 2. process_new_round_event forwards a TC its own rule forbids

The paper broadcasts =ProposalMsg<b, last_tc, high_commit_qc>= with whatever TC
brought the replica into the round. Its own well-formedness rule says a round-r
message carries the TC of r-1 *exactly when* its certificate is not from r-1.
When the new leader's block extends a QC from r-1 — the happy path — the TC is
forbidden, and a proposal carrying it is discarded by every honest replica,
including one running the paper's own =process_proposal_msg=. =core.go:273=
=justifyingTC= drops it.

** 3. local_timeout_round broadcasts a TC its own rule forbids

The same contradiction on the timeout side, and this one is not theoretical:
=local_timeout_round= ships =last_round_tc= unconditionally, while
well-formedness forbids it whenever =high_qc= is already from round-1. That
state is reachable, because =advance_round_qc= can return false — leaving
=last_round_tc= set — while =process_qc= has already raised =high_qc=. Every
honest peer then discarded the message, losing that sender's contribution to
the TC *including its f+1 amplification*. Found by a four-replica cluster run
reporting rejected messages; after =pacemaker.go:106= applied the same
=justifyingTC=, every run reports zero rejected.

* Smaller looseness, not previously recorded

Noticed while writing this and not in the deviation logs. None of it changes
the protocol; all of it is the kind of thing that costs a reader time.

- The paper's QC field paths do not match its own QC declaration. 3.3 declares
  =QC= with =vote_info, ledger_commit_info, signatures, author,
  author_signature=, but =execute_and_insert= reads =b.qc.block_id=,
  =commit_state_id_candidate= reads =qc.id=, and =process_vote= constructs a QC
  from =state_id= and =votes=. All four should be paths through =vote_info= or
  the declared names; the implementation reads them that way
  (=blocktree.go:95= via =types.go:128= =Block.ParentID=, =safety.go:101=,
  =blocktree.go:134-140=).
- Several procedures dereference a possibly-nil argument. =safe_to_extend= and
  =safe_to_timeout= read =tc.round= where the caller may pass nil;
  =process_certificate_qc= is called with =P.high_commit_qc=, which the message
  types allow to be absent; =advance_round_qc= reads =qc.vote_info.round=
  unguarded. Guarded at =safety.go:57=, =safety.go:90=, =core.go:183= and
  =types.go:90= respectively.
- =local_timeout_round= does not test =make_timeout='s result before building a
  message around it, although the procedure is declared as returning nil on
  refusal. Guarded at =pacemaker.go:95=.
- =reputation_leaders= is written to and never read down or pruned, so it grows
  for the lifetime of the replica. Pruned at =leader.go:78-82=.
