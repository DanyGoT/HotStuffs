#+title: DiemBFT v4 section 3, procedure by procedure

Where each procedure of the paper's section 3 pseudocode landed in this
package, and where it did not land verbatim.

The pseudocode itself is *not* reproduced here. The transcription is
=.claude/notes/diembft-pseudocode.md=, and it is the canonical copy: a second
one would drift. What follows restates each procedure in this codebase's
vocabulary and points at the code.

Bare file names are in =diem/=; anything else is written from the repository
root, except =diem.proto=, which is =proto/diempb/diem.proto=. References are
written =file:Symbol=, so they survive the code moving.

=README.org= covers what the package is and how it is laid out. This file
covers only the mapping.

* 3.1 Main

** EventLoop

The paper's outer loop. Split in three here, because the core is drivable at
three levels: =Core.Step= for state-machine unit tests, =Loop.Tick= for the
deterministic harness, =Loop.Run= in production.

- Implemented :: =loop.go:Run=, =Tick=, =events.go:Queue=, =Push=.
- Differs :: structurally only. The queue is the goroutine boundary and the
  only backpressure point in the replica; the paper has no concurrency model to
  place one in. No protocol difference.

** start_event_processing(M)

One switch over the sealed =Event= set, so the dispatch is exhaustive by
construction and needs no default case.

- Implemented :: =core.go:Step=; the event set is =events.go:Event= with its
  four members.
- Differs :: the paper dispatches a local timeout unconditionally. =Step=
  runs =Pacemaker.LocalTimeoutRound= only when the event's =Round= is still
  =Pacemaker.CurrentRound()=. The timer callback runs off the consensus
  goroutine and only enqueues, so a callback that had already fired when
  =startTimer= or =Stop= disarmed the timer is still sitting in the queue;
  running it would abandon a round the replica entered on a good certificate.

** process_certificate_qc(qc)

Feed the certificate to the block tree, then to leader election, then to the
pacemaker.

- Implemented :: =core.go:processCertificateQC=.
- Differs :: only in two details. A nil guard in =processCertificateQC=, because
  =HighCommitQC= is optional on the wire. And the paper's
  =Pacemaker.advance_round(qc.vote_info.round)= is =AdvanceRoundQC(qc)= here —
  see *Where the paper is self-contradictory*, item 1. The order is the
  paper's, and it matters: =LeaderElection.UpdateLeaders= reads the round the
  certificate arrived in, so it must run before the pacemaker advances past it.

** process_proposal_msg(P)

Advance on all three certificates the proposal carries, then check that the
block's round is the current round and that its sender and author both lead it,
then speculate and insert, then vote.

- Implemented :: =core.go:processProposalMsg=; the vote goes out to
  =LeaderElection.GetLeader(round+1)=, unicast, as the paper specifies.
- Differs :: no protocol difference. What changed is *where* authentication
  happens: signatures, quorum sizes, certificate well-formedness and signer
  order are checked at the edge (=diemnet/server.go:Proposal=,
  =verify.go:VerifyProposal=) before the message is queued. The three checks
  that remain here are the paper's own, and the leader check could not move
  anyway — =GetLeader= has a reputation path keyed on committed blocks, so a
  round's leader is a function of protocol state.

** process_timeout_msg(M)

Advance on the timeout's =HighQC=, its =HighCommitQC= and its =LastRoundTC=,
then accumulate it; a TC that completes advances the round and fires a new-round
event.

- Implemented :: =core.go:processTimeoutMsg=.
- Faithful :: no deviation.

** process_vote_msg(M)

Accumulate the vote; a certificate that completes is processed and a new-round
event fires.

- Implemented :: =core.go:processVoteMsg=.
- Differs :: =processVoteMsg= ignores votes more than =maxRoundLead=
  (=core.go:maxRoundLead=, 4) rounds ahead, or older than the previous round.
  The paper accepts all. Each distinct vote opens its own bucket, a faulty
  node can make every vote distinct, and buckets are only freed on commit —
  which its votes never cause. The window caps how many buckets it can open.
- Differs :: a new round starts only when a QC advances the round. The paper
  starts one on every QC, so a late QC made the leader propose twice in one
  round.

** process_new_round_event(last_tc)

If this replica leads the round it just entered, build a block over =HighQC=,
sign its id and broadcast the proposal.

- Implemented :: =core.go:processNewRoundEvent=. The payload comes from
  =core.go:Transactions= (a =Config= field), nil-checked there, which is this
  package's MemPool seam. The =sign= call is the only =crypto= call in
  =core.go=.
- Differs :: the paper forwards =last_tc= verbatim. =processNewRoundEvent=
  passes it through =core.go:justifyingTC=, which returns nil when the block's
  own QC is already from round-1. Forwarding it would produce a proposal that
  the paper's own well-formedness rule makes ill-formed, and that every honest
  replica — including one running the paper's =process_proposal_msg= — discards.
  See *Where the paper is self-contradictory*, item 2.

* 3.2 Ledger

** speculate(prev_block_id, block_id, txns)

Execute a block's payload over its parent's speculated state and store the
result under the block id.

- Implemented :: =ledger.go:Speculate=; the VM is the =Execute= field,
  defaulting to =hash.go:ExecuteHash=.
- Differs :: two things. The signature takes the whole =*Block= rather than the
  paper's three fields — all three are fields of the block, and
  =committed_block= must hand a whole block back, so the ledger holds it
  regardless. And a parent this replica never speculated stores *nothing* and
  returns the zero state. That is where the paper's missing
  block-sync lands: section 3 defines no way to fetch a block, so a replica
  that loses one proposal cannot speculate it, cannot vote on it, and cannot
  speculate its children either.

** pending_state(block_id)

The speculated state for a block, or absent.

- Implemented :: =ledger.go:PendingState=.
- Differs :: the last committed block answers too. Its
  children extend it and it is no longer in the pending map, so without this a
  block extending the commit frontier could never be speculated. The paper does
  not say either way.

** commit(block_id)

Commit the pending prefix ending at a block and discard the branches forking
below it.

- Implemented :: =ledger.go:Commit=; branch discard is =prune=, which drops
  orphans to a fixpoint.
- Differs :: two early returns the paper does not have. =Commit= returns when
  the block is already the frontier, which is the common case since every QC
  re-commits. It also returns when the block is not a descendant of the frontier
  — the missing-ancestor gap again, seen from the commit side: the frontier
  cannot walk back across a block that was never speculated. =forget= is a
  retention bound with no counterpart at all; see *Code with no counterpart in
  the paper*.

** committed_block(block_id)

A committed block by id, which is what =LeaderElection= walks back over.

- Implemented :: =ledger.go:CommittedBlock=.
- Faithful :: no deviation, except that the answer is bounded by =History=
  (=ledger.go:History=, default =defaultHistory=) rather than being a permanent
  store.

* 3.3 Block-tree

The paper defines the message types here as well as the module. Those first.

** The data types

- =VoteInfo= :: =diem.proto:VoteInfo=.
- =LedgerCommitInfo= :: =diem.proto:LedgerCommitInfo=; the paper's bottom
  =commit_state_id= is the zero hash, tested by =types.go:Commits=.
- =VoteMsg= :: =diem.proto:VoteMsg=.
- =QC= :: =diem.proto:QuorumCert=, with =types.go:QCRound= and =higher=, which
  is the paper's =max_round{}=.
- =Block= :: =diem.proto:Block=, built by =types.go:NewBlock=; the id formula
  =hash(author || round || payload || qc.vote_info.id || qc.signatures)= is
  =hash.go:blockID=.
- =TimeoutInfo= :: =diem.proto:TimeoutInfo=.
- =TC= :: =diem.proto:TimeoutCert=, plus =types.go:MaxHighQCRound=, the paper's
  =max(tc.tmo_high_qc_rounds)=.
- =TimeoutMsg= :: =diem.proto:TimeoutMsg=. =ProposalMsg= ::
  =diem.proto:ProposalMsg=.
- Well-formedness :: the paper states it as prose, not pseudocode; it is
  =types.go:wellFormed= with the two entry points =WellFormedProposal= and
  =WellFormedTimeout=.

One deviation in the types: the paper keeps a TC's =tmo_high_qc_rounds= and
=tmo_signatures= in two parallel vectors. =diem.proto:TimeoutVote= is one
slice of pairs instead. Each signature covers =(tc.Round, its own HighQCRound)=,
so verifying against the wrong partner would silently succeed for a different
sender, and parallel vectors are exactly the shape that permits that.

** process_qc(qc)

A certificate whose =LedgerCommitInfo= names a committed state commits that
block's *parent*, prunes the tree to it, and raises =high_commit_qc=; every
certificate raises =high_qc=.

- Implemented :: =blocktree.go:ProcessQC=; the tree prune is =prune=.
- Faithful :: no deviation. =prune= takes the root's round from the certificate
  rather than from a lookup, because the root may already
  have been pruned by an earlier commit and the QC carries its round.

** execute_and_insert(b)

Speculate the block, then add it to the pending tree.

- Implemented :: =blocktree.go:ExecuteAndInsert=.
- Faithful :: no deviation.

** process_vote(v)

Process the vote's commit certificate, bucket the vote by the digest of its
=LedgerCommitInfo=, and return a QC once a bucket reaches quorum.

- Implemented :: =blocktree.go:ProcessVote=; the author signature is produced
  there over =hash.go:qcSigsDigest=, and checked on receipt inside
  =verify.go:VerifyQC=.
- Differs :: three things.
  1. The paper accumulates a *set union over signatures*. With a randomised
     signature scheme two signatures by one replica differ byte for byte, so
     the union would not deduplicate and one sender could reach quorum alone.
     Deduplication is by signer.
  2. Deduplication is by =voterKey{round, signer}= (=blocktree.go:voterKey=),
     checked *before* the bucket is created, not within a bucket. The bucket key
     is a digest over fields the sender chooses, so a signer varying one of them
     opens a bucket per message without ever repeating itself inside one. An
     honest replica votes at most once per round — =safeToVote= requires the
     block's round to exceed =highestVoteRound=, which never decreases — so one
     entry per (round, signer) is all that can ever be legitimate.
  3. It canonicalises the signature set (=blocktree.go:canonical=) and drops
     the bucket once the certificate exists.

** generate_block(txns, current_round)

A block for the current round over the highest certificate known.

- Implemented :: =blocktree.go:GenerateBlock=, over =types.go:NewBlock= and
  =hash.go:blockID=.
- Faithful :: no deviation.

* 3.4 Safety

The module holds exactly two counters (=safety.go:highestVoteRound= and
=highestQCRound=) plus the private key,
which is what would let it live in a trusted component.

** increase_highest_vote_round(round)

- Implemented :: =safety.go:increaseHighestVoteRound=.
- Faithful :: no deviation.

** update_highest_qc_round(qc_round)

- Implemented :: =safety.go:updateHighestQCRound=.
- Faithful :: no deviation.

** consecutive(block_round, round)

#+begin_example
round + 1 == block_round
#+end_example

- Implemented :: =safety.go:consecutive=.
- Faithful :: no deviation.

** safe_to_extend(block_round, qc_round, tc)

A block may skip rounds only behind a TC for the round directly below it, and
only when its certificate is at least as high as every certificate that TC's
quorum reported.

- Implemented :: =safety.go:safeToExtend=, over =types.go:MaxHighQCRound=.
- Differs :: a nil guard in =safeToExtend=. The paper dereferences =tc.round=
  and =tc.tmo_high_qc_rounds= with no guard, while =safe_to_vote= calls it with
  a =tc= that may be nil.

** safe_to_vote(block_round, qc_round, tc)

Vote in monotonically increasing rounds, over a round strictly below this one,
and only when the QC or a TC justifies the round.

- Implemented :: =safety.go:safeToVote=.
- Faithful :: no deviation.

** safe_to_timeout(round, qc_round, tc)

Never report a =high_qc= below one already endorsed, never time out of a past
round, and only time out of a round the QC or a TC justified entering.

- Implemented :: =safety.go:safeToTimeout=.
- Differs :: two corrections, neither of them a change of intent. The paper
  writes =max(highest_vote_round - 1, qc_round)=; rounds are unsigned here, so
  round 0 is subtracted explicitly rather than wrapping.
  And the =tc= nil guard again.

** commit_state_id_candidate(block_round, qc)

The 2-chain commit rule: a vote for a block whose round directly follows its
parent's carries the parent's speculated state, so the quorum certifying the
block also certifies that commit. A gap in rounds commits nothing.

- Implemented :: =safety.go:commitStateIDCandidate=.
- Faithful :: no deviation. "Commits nothing" is the zero hash, which is the
  paper's bottom.

** make_vote(b, last_tc)

Re-verify the certificates, apply =safe_to_vote=, raise both counters, then
build the =VoteInfo= and =LedgerCommitInfo= and sign the latter.

- Implemented :: =safety.go:MakeVote=.
- Differs :: the paper puts =Ledger.pending_state(b.id)= inside the =VoteInfo=
  and would sign a bottom execution state when the lookup fails. =MakeVote=
  declines instead, and counts the decline. A vote is a claim about an
  execution result, and a replica that could not execute the block — because it
  never saw an ancestor, and the paper has no block-sync — has no result to
  claim. Note the ordering consequence: the counters move only on the path that
  produces a vote, so a declined vote does not burn the round.

** make_timeout(round, high_qc, last_tc)

Re-verify, apply =safe_to_timeout=, raise =highest_vote_round= to stop voting
in the round, and sign =(round, high_qc.round)=.

- Implemented :: =safety.go:MakeTimeout=; the digest is =hash.go:TimeoutDigest=.
- Faithful :: no deviation.

** valid_signatures(b, last_tc)

The paper calls this from both public procedures but never defines it.

- Implemented :: =safety.go:validSignatures=, which routes to
  =verify.go:VerifyQC= and =VerifyTC= —
  the same implementations the edge uses. Safety re-verifies deliberately: it
  holds the private key and is the one module assumed to survive the rest being
  compromised.

* 3.5 Pacemaker

** get_round_timer(r)

The paper leaves the formula open — "4*delta, or alpha + beta*commit_gap(r) if
delta is unknown".

- Implemented :: delegated to an exponential backoff, =pacemaker.go:Backoff=,
  read in =startTimer= and fed by =Grow= and =Reset=.
- Differs :: a choice within the paper's latitude rather than a deviation.
  There is no =Pacemaker= method of this name; the policy is a field.

** start_timer(new_round)

Stop the running timer, enter the new round, arm a timer for it.

- Implemented :: =pacemaker.go:startTimer=.
- Differs :: it also prunes =pendingTimeouts= below the new round. The paper's
  comment says only the current round's timeouts are needed but never drops the
  others. The timer callback may only enqueue, since it runs off the consensus
  goroutine.

** stop_timer(current_round)

- Implemented :: =pacemaker.go:Stop=.
- Differs :: no round argument. There is exactly one timer, so there is nothing
  to select.

** local_timeout_round()

Build this replica's timeout for the current round and broadcast it.

- Implemented :: =pacemaker.go:LocalTimeoutRound=.
- Differs :: four things.
  1. =save_consensus_state()= is absent — see *Procedures with no counterpart*.
  2. It returns when =MakeTimeout= declines. The paper
     broadcasts a =TimeoutMsg= built around the result unconditionally.
  3. It passes =lastRoundTC= through =justifyingTC=, for the
     same reason and by the same rule as the proposal path. See *Where the
     paper is self-contradictory*, item 3.
  4. It re-arms the timer. The paper stops it and waits for a
     TC, which leaves a replica whose broadcast was lost with no timer at all;
     here the timeout is retransmitted until a QC or a TC moves the round.

** process_remote_timeout(tmo)

Accumulate a timeout for a round not already behind us; at f+1 senders time out
locally as well (Bracha amplification), at 2f+1 return the TC.

- Implemented :: =pacemaker.go:ProcessRemoteTimeout=; the
  thresholds are the =faulty+1= and =quorum= cases of its switch.
- Differs :: two things.
  1. It returns early on a duplicate sender. The paper puts its
     two count tests *outside* the duplicate guard, and re-adding a sender to a
     set does not change its size, so a resent timeout re-runs both: a second
     Bracha broadcast, and a second TC for a round already abandoned, which then
     drives an ill-formed proposal. This implementation retransmits timeouts
     while a round is stuck, so the duplicate is certain, not hypothetical.
  2. It sorts the assembled TC's votes into signer order. Timeouts arrive in
     whatever order the network delivers them, and a receiver rejects a
     non-canonical certificate (=verify.go:VerifyTC=), so a replica whose
     timeouts arrived out of ID order would otherwise assemble a TC that neither
     its peers nor its own =Safety.validSignatures= would accept.

** advance_round_tc(tc)

- Implemented :: =pacemaker.go:AdvanceRoundTC=.
- Faithful :: no deviation.

** advance_round_qc(qc)

- Implemented :: =pacemaker.go:AdvanceRoundQC=.
- Faithful :: no deviation. The =Reset= call in =AdvanceRoundQC= is
  =get_round_timer='s business, not the round logic's.

* 3.6 MemPool

** get_transactions()

The only procedure the paper declares in this module, with no body.

- Implemented :: =mempool.go:GetTransactions=, a bounded FIFO handing out at
  most =batch= per call. =Core= reaches it through the =Config.Transactions=
  function (=core.go:Transactions=), called in =processNewRoundEvent=; in
  production it is =replica/payload.go:Transactions=.
- Differs :: nothing the paper constrains. =mempool.go:Add= is
  the ingress the paper does not define; an empty result is normal and still
  produces a block, since the pipeline is what commits the blocks below it.

* 3.7 LeaderElection

** get_leader(round)

The reputation-elected leader when one was elected for the round, otherwise
round-robin with two rounds per leader:

#+begin_example
validators[(round / 2) mod |validators|]
#+end_example

- Implemented :: =leader.go:GetLeader=.
- Faithful :: no deviation. =validators= is sorted at construction
  (=leader.go:NewLeaderElection=) so every replica indexes the same rotation.

** update_leaders(qc)

Elect the leader of the round after next, but only when the certificate shows a
contiguous 2-chain that this replica is exactly one round past.

- Implemented :: =leader.go:UpdateLeaders=; the predicate is its
  =extendedRound= and =qcRound= test.
- Differs :: three additions, none of them to the predicate. A nil guard; the
  write happens only when the election succeeded (see below); and it drops
  entries for rounds already left behind, which the paper's map would accumulate
  forever.

** elect_reputation_leader(qc)

Walk back over committed blocks collecting the signers of the last
=window_size= certificates and the authors of the last =exclude_size= blocks,
then pick deterministically from the difference, seeded on the certificate's
round.

- Implemented :: =leader.go:electReputationLeader=;
  =pick_one(seed)= is =pick=, which hashes the round rather than
  taking it modulo the candidate count, so consecutive seeds spread across the
  set.
- Differs :: two termination guards the paper's loop lacks. Two =CommittedBlock=
  lookups in =electReputationLeader= stop when the ledger no longer holds the
  next block back, which happens both early in a run and once =History= has
  dropped old blocks; the paper's loop runs off the end of a short history. It
  also returns "no election" when the difference is empty — the paper argues it
  is non-empty, which holds only once the window is full — and round-robin then
  stands, the same fallback a replica that saw no commit uses.
- Reproduced faithfully, and worth knowing :: the walk steps over *alternating*
  committed blocks, not consecutive ones. Each iteration looks up
  =current_qc.vote_info.parent_id= and then sets =current_qc <-
  current_block.qc=, which skips a block per step. That is the algorithm as the
  paper specifies it.

* Procedures with no counterpart

- =save_consensus_state()= (3.5, called from =local_timeout_round=) :: the two
  counters it would persist are =Safety='s (=safety.go:highestVoteRound= and
  =highestQCRound=), and this is a prototype with no durable state, so
  persisting them would have nothing to recover into. Recorded in
  =pacemaker.go:LocalTimeoutRound=. A replica that restarts here restarts from
  genesis; the paper's version could restart from its last vote.

Two more are implemented but not as procedures, noted so nobody hunts for them:
=get_round_timer= is a policy field rather than a method (=pacemaker.go:dur=),
and =stop_timer= drops its round argument (=pacemaker.go:Stop=).

* Code with no counterpart in the paper

Section 3 is a protocol, not a program. These are what it takes to run one.

- Bootstrap :: =core.go:Start= — advance on the genesis certificate and fire the
  first new-round event. The paper never says how round 1 begins. The genesis
  block and its certificate are =genesis.go:genesisBlock= and =genesisQC=: two
  objects, not one, because a block's id covers a QC but no certificate can name
  the genesis block before its id exists.
- The edge verifier :: =verify.go:Verifier=, called from
  =diemnet/server.go:Proposal=, =Vote= and =Timeout=. The paper's only
  verification hook is =valid_signatures= inside =Safety=. Splitting it out is
  what lets signature checking run on the handler goroutines, in parallel across
  senders. Two of its checks have no paper counterpart at all: =VerifyProposal=
  rejects a block whose QC is not from a round below its own (well-formedness
  permits it on the TC branch, and =safeToVote= catches it only after the
  pacemaker has advanced and the block has been speculated), and =VerifyTC=
  rejects a TC for round 0, which no replica ever times out of.
- Canonical certificate encoding :: =blocktree.go:canonical=,
  =pacemaker.go:ProcessRemoteTimeout=, the strict-increase and
  every-signature-valid checks in =verify.go:verifyCert= and =VerifyTC=, and the
  low-s form in =crypto/ecdsa.go:Sign= and =Verify=. A block id hashes its
  parent certificate's signatures byte for byte (=hash.go:blockID=). If the
  same quorum could be reordered, padded with junk or re-encoded, it would
  yield many valid block ids, and each would enter the block tree and the
  speculation tree.
- The round bounds :: =core.go:maxRoundLead= and the previous-round floor,
  both applied in =processVoteMsg=. The paper puts no limit on how far ahead
  or behind a vote's round may be.
- The missing-ancestor counter :: =safety.go:declinedMissingAncestor= and its
  accessor =DeclinedMissingAncestor=, incremented in =MakeVote= and surfaced
  through =core.go:State=, whose =DeclinedMissingAncestor= field copies it.
  Section 3 has no block-sync and none was added; this counter is the price tag.
  It is the number the report should quote about the gap, rather than an
  argument about whether section 3 is livelocked in principle.
- Retention :: =ledger.go:History= and =forget=.
  The paper's ledger is unbounded; =committed_block= must still answer for
  everything =elect_reputation_leader= walks back over, so the bound is what
  =electReputationLeader='s termination guard exists for.
- The event queue and driver :: =events.go:Queue=, =loop.go:Loop=.
  The goroutine boundary, the only backpressure point, and the queue high-water
  mark.
- The seams :: =seams.go:Transport=, where the paper writes "send" and
  "broadcast", plus =Crypto= and =Clock=, which the paper assumes.
- Domain-separated digests :: =hash.go:domainBlock=, =domainVoteInfo=,
  =domainLedgerCommit=, =domainTimeout=, =domainQCSigs= and =domainState=. The
  paper writes =hash()=. Six distinct tags keep a vote signature from ever
  verifying as a timeout signature, or either as a block id.
- Observability :: =core.go:State=, the snapshot type and its accessor, and the
  =Observer= hook (=core.go:Observer=).
- MemPool ingress :: =mempool.go:Add=.

* Where the paper is self-contradictory

Three places, and they are the most interesting material here for the report:
all three are cases where following section 3 literally produces behaviour that
section 3 itself rejects.

** 1. advance_round is called by a name that does not exist

=process_certificate_qc= calls =Pacemaker.advance_round(qc.vote_info.round)=
and =process_timeout_msg= calls =Pacemaker.advance_round(tc)= — one with a
round, one with a certificate. The Pacemaker module (3.5) defines neither; it
defines =advance_round_qc(qc)= and =advance_round_tc(tc)=. Read as the typed
pair, which is what =core.go:processCertificateQC= and =processTimeoutMsg=
implement. Harmless, but it
is the reason a reader comparing the two modules side by side finds no match.

** 2. process_new_round_event forwards a TC its own rule forbids

The paper broadcasts =ProposalMsg<b, last_tc, high_commit_qc>= with whatever TC
brought the replica into the round. Its own well-formedness rule says a round-r
message carries the TC of r-1 *exactly when* its certificate is not from r-1.
When the new leader's block extends a QC from r-1 — the happy path — the TC is
forbidden, and a proposal carrying it is discarded by every honest replica,
including one running the paper's own =process_proposal_msg=.
=core.go:justifyingTC= drops it.

** 3. local_timeout_round broadcasts a TC its own rule forbids

The same contradiction on the timeout side, and this one is not theoretical:
=local_timeout_round= ships =last_round_tc= unconditionally, while
well-formedness forbids it whenever =high_qc= is already from round-1. That
state is reachable, because =advance_round_qc= can return false — leaving
=last_round_tc= set — while =process_qc= has already raised =high_qc=. Every
honest peer then discarded the message, losing that sender's contribution to the
TC *including its f+1 amplification*. Found by a four-replica cluster run
reporting rejected messages; after =pacemaker.go:LocalTimeoutRound= applied the
same =justifyingTC=, every run reports zero rejected.

* Smaller looseness, not previously recorded

Noticed while writing this and not in the deviation logs. None of it changes
the protocol; all of it is the kind of thing that costs a reader time.

- The paper's QC field paths do not match its own QC declaration. 3.3 declares
  =QC= with =vote_info, ledger_commit_info, signatures, author,
  author_signature=, but =execute_and_insert= reads =b.qc.block_id=,
  =commit_state_id_candidate= reads =qc.id=, and =process_vote= constructs a QC
  from =state_id= and =votes=. All four should be paths through =vote_info= or
  the declared names; the implementation reads them that way
  (=blocktree.go:ExecuteAndInsert= via =types.go:parentID=,
