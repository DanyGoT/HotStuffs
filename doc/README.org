* Limits

- Block sync is one block per request. A gap is walked back one block at a time
  while the chain keeps growing, and peers keep 512 committed blocks
  (=diem/ledger.go:History=). In the sim, a replica that misses 256 consecutive
  proposals or more never catches up; that needs state sync.
- =highest_vote_round= is not persisted. =diem/pacemaker.go:LocalTimeoutRound= has
  no =save_consensus_state()=, so a restarted replica can vote twice in a round.
- Keys are seeded. Without =-keys=, every replica derives the same insecure key
  set (=crypto/ecdsa.go:SeededKeys=).
- No equivocation evidence. Conflicting messages from one replica are not
  recorded or reported.
- No verified sender identity. Gorums does not tell a handler which peer sent a
  message, so this code trusts the =sender= field and checks signatures
  (=diemnet/server.go:handler=). Fields without a signature are not covered.
  See [[https://github.com/relab/gorums/issues/325][relab/gorums#325]].
